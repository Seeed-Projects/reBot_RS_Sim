# 双臂桌面：纯接触、渲染、视觉范围与动作组合

本轮承接 `next-optimization-goal.md` 的四项要求。当前网页默认使用 RGB-D 视觉和纯接触夹持，
菜单提供“勺子入杯”和“会合展示后分别归位”。本地验证已完成，用户于 2026-10-24 授权推送；发布状态以 GitHub Actions 的构建与部署结果为准。

## 纯接触夹持

杯柄与两指的碰撞已启用。协作夹爪使用独立命名配置：PD 1800 / 18、滑动夹爪执行器控制力上限 12 N，
闭合指令限速 0.04 m/s，2 N 预紧力在 0.5 s 内逐渐建立；此配置不覆盖原 Web / ROS 默认值。
接触求解使用 elliptic cone 和 `impratio=10`，初始物品沉降 2.5 s。
抬升需要实测三根耦合指关节闭合且低速、至少 0.65 s 的夹紧等待、杯柄每指 ≥0.6 N、勺柄每指 ≥0.2 N。

`grasp-contact-sensor.js` 使用 `mj_contactForce` 测量承力接触，读取指面局部坐标中的力加权压力中心。
`hold-monitor.js` 对两侧压力中心低通滤波，两侧共同漂移超过 4 mm 且持续 0.06 s 时停止；
双侧承力接触缺失超过 0.10 s 也停止。杯子落桌时以实际桌面支撑力 >0.1 N 确认承重转移，
避免把此时接触压力重新分布误判为悬空滑落。异常明确停止，没有宣称实现自动重新抓取。

`test-contact-grasp.mjs` 的完整入杯测试 13/13 通过，覆盖标准摆放与 12 个固定种子、
X ±10 mm / Y ±8 mm / yaw ±0.08 rad、摩擦 0.9 / 1.0 / 1.1 倍及不规则步进。
逐批读取 equality 状态，断言杯、勺两个抓取 weld 始终关闭；释放后再运行 1 s 物理，检查入杯和直立。
最大双侧触觉漂移指标为杯 2.631 mm、勺 3.439 mm，最大指面穿透 0.0181 mm。
这项漂移是触觉接触斑块指标，不是物体运动真值。人为沿勺柄滑移 9 mm 与横向失握 40 mm，
分别触发 `contact-slip-detected` 与 `contact-grasp-lost`，均未误报完成。

最终退让路径的第二任务物理归位测试 3/3 通过，单独记录在 `contact-return.json`，全过程同样检查 weld 关闭。
释放后再运行 1 s，最大归位位置误差为杯 4.830 mm、勺 0.712 mm。
入杯完整报告为 `contact-grasp.json`；辅助夹持回归 `cooperation-benchmark.json` 保留作历史基线，不计入纯接触成功率。

## 图像适应范围

图像测试实际渲染俯视和侧上方 RGB / 深度，再由独立的像素模块估计位姿。
控制与视觉成功判据不接收物体 body ID 或物体真值；真值仅由测试评分器在推理后用于计算误差。
接触传感和碰撞保护是独立的仿真反馈。真实页面使用 Worker；测试 harness 另检验相同感知模块的扰动范围。

| 测试组 | 应完成 / 实际完成 | 应拒绝 / 正确停止 | 最大杯 / 勺位置误差 |
| --- | --- | --- | --- |
| `visual-contact.json` | 6 / 6 | 2 / 2 | 3.720 / 1.406 mm |
| `visual-extended.json` | 7 / 7 | 4 / 4 | 3.721 / 1.408 mm |
| `visual-return.json` | 2 / 2 | 0 | 1.507 / 1.373 mm |

标准组覆盖随机摆放、±10% 摩擦、RGB ±2 级、深度 ±0.15 mm、约 2.7% 丢点、
4 mm 抓取前移位、短暂遮挡恢复及持续遮挡 / 陈旧帧停止。
扩展组覆盖光照强度 0.65 / 1.35 倍与曝光 0.9 / 1.15、蓝色 / 暖色釉面及不同粗糙度、
同杯口尺寸和杯耳的直壁杯、12 mm 抓取前移位、15% RGB / 深度同步条带缺失。
条带是传感器像素缺失注入，不是新增实物遮挡物。

缺失目标测试将真实杯子或勺子移出相机视野，保留水果、支撑块及背景。
两项均未把剩余物品识别为可信的缺失目标，最多三次观察后停止；该小样本记录为 0/2 误接受，
不能外推为通用识别的误报率。所有图像测试的浏览器异常数为 0。

这是已标定杯勺族的颜色与几何拟合，尚未验证任意杯径、透明杯、多杯多勺选择或真实相机域迁移。
释放后使用新的像素拟合，并要求相隔至少 0.35 s 的两次观测均满足放置要求、杯勺各移动 <3 mm。
归位复核以初始图像位置作为搜索先验，最终位置仍由当前图像拟合，允许归位误差 <10 mm。

## 可组合动作与页面

`cooperative-actions.js` 提供有界运动、接触闭合、有限重观察、杯口对准 / 插入判断、释放和稳定复核；
持稳由 `hold-monitor.js` 提供。`cooperation-geometry.js` 负责两种配方的目标，执行器共享上述动作。
第二配方复用观察、取杯取勺、抬升、会合持稳，然后先回到支撑块上方、缓慢下降、分别释放、退出相机视野，
最后从新图像确认归位。归位过程中保持碰撞预检，没有屏蔽支撑块碰撞来通过测试。

`test-cooperative-actions.mjs` 检查陈旧帧恢复、最多三次重试、无效姿态、取消及独立稳定复核。
实际页面 `test-visual-ui.mjs --hardware` 完成两项纯接触 Worker 视觉任务，
检查三路独立且随动作变化的相机、折叠、暂停 / 继续、复位、任务切换及 390 px 手机无横向溢出。
开发页面和最终生产包均通过这组测试，证据为 `visual-ui.json` / `visual-ui-production.json`
及 `visual-ui-desktop.png` / `visual-ui-mobile.png`（截图为最后一次生产包运行）。
当前仍是两种预设配方，不是自然语言规划器。

## 渲染与内存

本机 Chrome 实际使用 AMD Radeon 780M / ANGLE D3D11，支持 WebGL2 GPU timer query。
对照测试在同一 1100 × 850 页面中显示三路相机，依次切换相同的六个视角，
分别使用 `meshDetail=full` 与默认 balanced；CPU 提交和 GPU 时间排除首次加载窗口，按新增主画面绘制统计。
本轮硬件数据与上一轮 SwiftShader 数据分开，不将软件 GPU 耗时当作用户硬件耗时。

机械臂仅简化底座和连杆显示网格，保留属性接缝；按各相机投影误差估算的 0.8 px 阈值决定是否恢复完整网格。
夹指、腕部相机、杯和勺保持完整分辨率；RGB 与深度的一对图像使用同一精度。
28 个机械臂网格实例的潜在面数从 1,222,768 降至 699,404，实际使用随视角变化；
最大顶点位移约 1.030 mm。背景家具、植物曲面适量降低细分，碰撞几何保持原定义。

| 指标 | 完整网格 | balanced |
| --- | --- | --- |
| 同一桌面视角主画面三角面 | 1,564,662 | 1,020,522（减少 34.8%） |
| 主画面绘制调用 | 147 | 147 |
| 新增 7 次主画面 CPU 提交均值 | 3.743 ms | 4.114 ms |
| 新增 7 次主画面 GPU 均值 | 15.023 ms | 13.600 ms |
| 保留几何数组 | 21.347 MB | 24.658 MB |
| WASM 线性内存容量 | 1,455.096 MB | 1,455.096 MB |
| 本次加载时间 | 22.699 s | 22.730 s |

本次短测 GPU 均值约降低 9.5%，CPU 提交略升、加载无明显变化；7 次新增绘制不足以证明跨设备或稳定帧率收益。
后续进入等待优化另有同一生产包的前后实测，见 [进入等待优化](startup-optimization-verification.md)；
上表保留本轮渲染优化时的历史加载数据。
三路相机均实际出图，单一 WebGL 上下文，两组页面异常数均为 0；截图对照已检查。
初始几何数组按最后相机的活动网格统计，因此与上表主画面三角面计数口径不同；保留数组额外包括缓存中的原 / 简化网格。
同次 JS 堆快照为 60.631 / 51.151 MB，受 GC 和采样时机影响，不作为确定的内存优化收益。
原始数据为 `render-full.json` / `render-balanced.json`，截图为同名 PNG。
原网格和简化网格同时保留，保留几何数组增加约 3.312 MB，因此不把显示面数降低表述为内存降低。
对照测试的 WASM 初始化线性内存容量快照约 1.455 GB，生产包该快照约 1.535 GB；
分配峰值和加载过程会影响容量，这与进程实际驻留内存、GPU 内存不是同一指标。
本轮没有解决原始物理网格加载体积，尚未测量浏览器 GPU 进程的完整驻留内存。

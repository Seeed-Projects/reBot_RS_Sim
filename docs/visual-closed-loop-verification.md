# 双臂视觉闭环：上一轮实施与验收记录

本文件保留上一轮辅助夹持版本的运行证据。当前默认已改为纯接触夹持，并增加第二项协作任务；
本轮代码、性能和扩展视觉验收见 `next-optimization-verification.md`。
下表中的默认模式、纯接触失败和 SwiftShader 数据只描述上一轮修订，不代表当前实现。

目标：完成此前提出的可靠性、相对坐标、双臂碰撞检查、性能、参数一致性和视觉闭环优化，并检查实际运行结果。

## 验收范围

- 感知输入为真实渲染的 RGB / 深度像素与相机标定；视觉算法和视觉任务规划不能读取物体的仿真位姿。
- 从图像估计杯子和勺子的位姿、置信度，生成物体相对抓取目标。
- 执行过程中重新观察，检测移位、遮挡、陈旧帧、抓取偏差；允许有限次重新观察 / 规划，无法确认时停止。
- 入杯前用新的视觉观测修正目标；释放后退开机械臂，重新观察，按图像估计结果确认放置，不能用物理真值宣布视觉任务成功。
- 双臂轨迹检查覆盖运动途中、自碰、双臂之间和环境；速度 / 加速度有界，实际意外碰撞应停止并报告原因。
- 辅助夹持明确标注；独立验证接触、闭合、穿透和纯接触模式，不能把辅助约束成功率当作纯摩擦抓取能力。
- 记录物理、规划、感知、渲染耗时及内存相关指标；优化 IK 与多相机开销，避免新增重计算阻塞页面操作。
- Web / ROS 共用关节限制、单位与控制参数来源，保留 ROS 参数覆盖能力；本目标不把尚未连接的真机校准宣称为已验证。
- 自动化覆盖随机摆放 / 朝向 / 摩擦、图像噪声 / 遮挡 / 陈旧帧、执行中物品移动、错误目标、碰撞和失败恢复。
- 浏览器实际运行视觉协作，检查桌面和手机布局、三路相机、暂停、复位和模式切换；运行生产构建与 CI 对应检查。

## 复现命令

在 `web_mujoco` 中运行：

```bash
npm run test:ci
npm run test:contact
npm run test:vision
node scripts/test-vision.mjs --perturbed
npm run test:visual-ui
GITHUB_PAGES_BASE=/reBot_RS_Sim/ npm run build
```

Windows PowerShell 构建前使用 `$env:GITHUB_PAGES_BASE='/reBot_RS_Sim/'`。
Windows 浏览器测试默认调用本机 Chrome；Linux CI 会先安装 Playwright Chromium。
报告目录被 Git 忽略，CI 配置会上传 JSON 供检查；上表记录的是本地已执行结果。

## 验证边界

- 视觉算法是针对当前杯子、勺子、光照和工作区域的颜色与已知几何拟合，没有训练通用识别模型；已验证摆放范围为 X ±10 mm、Y ±8 mm、yaw ±0.08 rad。
- 图像扰动包括深度 ±0.15 mm、RGB ±2 级以及约 2.7% 丢点；相机外参使用仿真标定，尚未验证真实相机标定与域迁移。
- 路径检查沿用 MuJoCo 碰撞近似及模型已有的连杆排除规则；速度 / 加速度限制针对运动指令，真实接触动力学还受模型、增益和摩擦影响。
- 性能数据来自本机 Chrome / SwiftShader，不能当作所有设备的帧率保证。异步读回释放等待期间的主线程，但无法缩短 GPU 实际绘制时间；本轮单次采样等待最大 5.12 s，首次主画面绘制 / 着色器编译最大 6.17 s，软件 GPU 仍不能流畅预览。JS 堆与图形资源计数不等于完整 WASM / GPU 进程内存。
- 桌面默认杯勺任务仍使用辅助 weld；分类整理使用摩擦接触。视觉成功率不等于无辅助夹持或真机成功率。
- 独立纯接触杯勺实验尚不能稳定搬运杯子，当前增益 / 杯柄接触下会在抬升时失去接触；该模式只作为物理诊断，页面默认不开放它。
